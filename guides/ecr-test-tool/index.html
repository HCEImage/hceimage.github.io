ECR Test Tool

Exercise payment-terminal integrations with an ECR simulator

Android · Desktop

Connect to an authorized terminal or the built-in Local POI, run nexo Retailer operations and inspect the request, response and validation evidence.

Before starting

  • Use synthetic data and a terminal or test host that you are authorized to access.
  • Choose the nexo Retailer profile expected by the terminal. The application supports Retailer V5 (MUG 8.0 / CASP V05) and Retailer V4 (MUG 4.1-LW / CASP V01).
  • For an external terminal, obtain its test IPv4 address, TCP port, supported services and session requirements. For an isolated local exercise, enable Built-in terminal simulator in Settings.

ECR Test Tool is a diagnostic Sale System, not a payment processor or certification suite. It does not authorize a real payment or control decisions made by an external terminal or host.

Connect and choose a session

  1. In Connection, select the protocol profile and either an external terminal or the Local POI target.
  2. Enter the external endpoint when needed and select Connect. The Local POI uses a loopback endpoint created for that connection.
  3. Choose a session mode: Managed maintains a Login-to-Logout session, Without login sends operations directly, Per transaction wraps a supported operation, and Manual exposes Login and Logout controls.
  4. Review the connection state before starting an operation. Changing connection settings closes the active target and clears dependent operation state.

Run an operation

Operation shows the actions supported by the selected profile: Sale, Refund, Reversal, Reconciliation, Status check and Abort. Enter the fields required for the selected action; the main button names the action it will start. Lifecycle messages and automatic receiver responses appear in the result timeline rather than as manual operations.

Abort addresses an active exchange using its Exchange ID and a reason. A successful Abort completes the original service with FAIL/ABRT; an unprocessable request can produce MessageRejection. Cancel exchange is different: it interrupts the local exchange and closes its TCP transport without sending an Abort message.

Use the Local POI for repeatable scenarios

Automatic mode returns a successful response for a supported request. Manual mode opens the Local POI screen so you can choose approved, declined, timeout, malformed XML, MessageRejection or connection loss; an approved payment can also use a supplied authorization code. A timed-out payment remains active so a later Abort can exercise the FAIL/ABRT path.

Local POI results test the application's own ECR-to-POI path. Repeat significant cases against the actual authorized terminal because its configuration, kernel, host and error handling may differ.

Inspect and validate the exchange

The timeline shows outgoing requests, incoming responses, status and timing. Expand a message to inspect its XML and validation findings. Implemented messages pass XML security, envelope, selected-profile, official XSD and supported Message Usage Guide checks. A reported validation pass does not establish full nexo conformance or certification; message security is outside the tool's integration scope.

For external TCP targets, the ECR is the client. A frame is a UTF-8 ISO 20022 XML Document ending at </Document>; the document limit is 2 MiB and the response timeout is 15 seconds. An external terminal must use the matching namespace and preserve identifiers needed for response correlation.

Keep local evidence

History groups a connection from Connect to Disconnect or connection loss into one run, with its session cycles and operations. Filter by result, protocol or operation, add a note, then export a summary or detailed Markdown, HTML or PDF report. Detailed reports and high-detail platform logs may contain raw XML and synthetic test values. Review them before sharing.
