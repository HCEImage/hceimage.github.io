EMV Card Analyzer

Inspect supported contactless card applications

Android

Run a bounded EMV analysis over Android NFC, follow the APDU exchange and preserve diagnostic results locally.

Before starting

  • Use an Android device with NFC enabled.
  • Analyze only cards and test media that you are authorized to inspect.
  • Keep other NFC cards and tags away, and hold the card steadily within the phone's NFC field during analysis.

EMV Card Analyzer is a bounded diagnostic reader, not a payment kernel. It does not authorize transactions, validate issuer cryptography or determine whether a card is genuine.

Run an analysis

  1. Open the Analyzer and confirm that NFC is available and enabled.
  2. Start an analysis, then hold the contactless card against the device's NFC antenna.
  3. Keep the card in place while the application performs bounded directory selection, application selection, processing-options retrieval and supported AFL record reading.
  4. Keep the card in place until the app reports Completed, Incomplete, Unsupported, Interrupted or Failed.

Understand the result

Completed means that the supported analysis procedure reached its normal boundary. Incomplete preserves useful data when one or more applications could not be read completely. Unsupported identifies a card technology or application outside the supported reading procedure. Interrupted identifies lost communication, while Failed provides the available technical reason.

Compatibility varies between cards, devices and application profiles. An incomplete analysis does not by itself establish that a card is invalid.

Inspect APDU and EMV data

Application details organize discovered records and tags. The APDU timeline exposes raw commands and responses with contextual command, status-word, BER-TLV and DOL decoding where their meaning is known. All tags is an offline view of the already captured analysis, not an additional card read. Bundled Tag reference and APDU response-code screens help interpret recognized values without sending analysis data to a network service.

Use history, reports and traces

Analysis snapshots and optional notes are stored locally on the device. History supports result filtering, single-record deletion with Undo, clearing history, detailed report export and portable diagnostic traces through Android system interfaces. Reports can be saved or shared in Markdown, HTML or PDF; Trace exports a native JSON file. Import trace opens a local file for preview; choose Save to history only if you want to keep that imported analysis.

Full evidence exports may contain captured APDUs, notes and sensitive card data. Redacted exports remove card-derived values and notes while preserving diagnostic structure. Redacted is not a guarantee of anonymity: review the retained diagnostic context before sharing either form. An imported Redacted trace cannot restore the removed values. Review the selected evidence level and resulting file before sharing it.

A .hceimage.json trace identifies itself as com.hceimage.diagnostic / emv-analysis. It is a recorded diagnostic result, not an HCE card profile. See the trace format and usage guide for its structure, import checks and evidence boundary.

Settings and data safety

Settings controls analysis lifecycle, an optional no-card timeout, history retention, appearance and Logcat detail. Release builds default to session-level diagnostics; choosing APDU-level logging can place complete card data in local device logs. The summary masks card numbers until explicitly revealed, but APDU details and Full evidence exports can still contain sensitive values. Check screenshots, clipboard contents and exported files before sharing them.
