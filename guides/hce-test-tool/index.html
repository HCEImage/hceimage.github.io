HCE Test Tool

Test contactless terminal flows with synthetic card profiles

Use Android host card emulation to present a selected test profile, inspect the APDU exchange and review the resulting flow in one place.

Before starting

  • Use an Android device with NFC host card emulation support and NFC enabled.
  • Use only an authorized external contactless reader or payment terminal configured for testing.
  • Keep the test host and terminal configuration available when interpreting authorization or kernel-specific behavior.

HCE Test Tool contains synthetic test card data and is intended exclusively for development, integration testing and controlled test environments. It cannot perform real payments.

Run a test

  1. Choose the payment brand and a card profile that matches the scenario you want to exercise.
  2. Review the profile summary and open its test guidance for profile-specific expectations.
  3. If the authorized test host requires different test credentials, configure supported values under Test security data. Profile defaults remain unchanged when no override is applied.
  4. Start emulation and present the Android device to the reader or terminal.
  5. Keep the device in position until the application reports a completed, failed or interrupted outcome.

Inspect the exchange

The live timeline records commands and responses as the terminal communicates with the selected profile. Open an entry to inspect the raw APDU together with contextual command headers, status words, BER-TLV data, DOL values and recognized payment-scheme tags.

The result view compares the observed exchange with the expected profile flow. A failed or interrupted result is diagnostic context, not by itself proof of a terminal defect: reader configuration, terminal kernels and processing outside the emulator can affect the outcome.

Use history and reports

Completed, failed and interrupted attempts are kept locally. History filters help isolate an outcome, while session details preserve validation checks, the APDU timeline and optional test notes. Diagnostic reports can be saved or shared in Markdown, HTML or PDF when an integration result needs to be reviewed outside the application.

Handle test security data carefully

Only explicitly authorized test values belong in Test security data. Custom values are masked by default, validated before use and retained in memory only. They are not written to card profiles, history, reports, logs, clipboard output or backups. Never enter production issuer keys.
