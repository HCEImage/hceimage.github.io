HCE Test Tool

Test contactless terminal flows with synthetic card profiles

Android

Use Android host card emulation to present a selected test profile, inspect the APDU exchange and review the resulting flow in one place.

Before starting

  • Use an Android device with NFC host card emulation support and NFC enabled.
  • Use only an authorized external contactless reader or payment terminal configured for testing.
  • Keep the test host and terminal configuration available when interpreting authorization or kernel-specific behavior.

HCE Test Tool contains synthetic test card data and is intended exclusively for development, integration testing and controlled test environments. It cannot perform real payments.

Run a test

  1. Choose the payment brand and a card profile that matches the scenario you want to exercise.
  2. Review the profile summary and open its test guidance for profile-specific expectations.
  3. If the authorized test host requires different test credentials, configure supported values under Test security data. Profile defaults remain unchanged when no override is applied.
  4. Start emulation and present the Android device to the reader or terminal.
  5. Keep the device in position until the application reports a completed, failed or interrupted outcome.

Inspect the exchange

The live timeline records commands and responses as the terminal communicates with the selected profile. Open an entry to inspect the raw APDU together with contextual command headers, status words, BER-TLV data, DOL values and recognized payment-scheme tags. Command/response timings and session duration help locate delays; they do not measure the terminal's complete payment processing time.

The result view compares the observed exchange with the expected profile flow. A failed or interrupted result is diagnostic context, not by itself proof of a terminal defect: reader configuration, terminal kernels and processing outside the emulator can affect the outcome.

Use history and reports

Completed, failed and interrupted attempts are kept locally. History filters help isolate an outcome, while session details preserve validation checks, the APDU timeline and optional test notes. Delete a single record or clear history when it is no longer needed. Diagnostic reports can be saved or shared in Markdown, HTML or PDF when an integration result needs to be reviewed outside the application.

Choose Full evidence for captured values or Redacted to retain structural diagnostics while omitting card-derived values and notes. Redacted is not a guarantee of anonymity: review the retained diagnostic context before sharing either form. Single-record deletion offers Undo. Settings controls history retention, appearance, Logcat detail, result vibration and emulation timeout. High-detail logs and Full evidence reports can contain synthetic card data; review them before sharing.

Handle test security data carefully

Only explicitly authorized test values belong in Test security data. Values entered in the Emulator are masked by default, validated before use and retained in memory only. They clear after the next emulation with that profile starts unless you choose Keep until the app is closed; you can also remove them earlier. These temporary overrides are not written to card profiles, history, reports, logs, clipboard output or backups. Separately, synthetic defaults included in an imported profile persist with that profile file. Never enter production issuer keys.

Import a card profile

Choose Card profiles → Import profile to open a native .hceimage.json definition. Review the preview before saving it. The file identifies itself as com.hceimage.definition / card-profile; the app validates its profile schema, unique Profile ID, supported brand, AIDs, APDU behavior and supplied test security data. Bundled profiles cannot be replaced or deleted.

Imported profiles appear alongside bundled profiles and can be isolated with the Profile source filter. Swipe an imported card or use Delete in its detail; both routes provide Undo. Deleting a profile does not delete its existing session history; repeating a saved session requires an available profile with the same Profile ID. Profile-default synthetic test security data in an imported file persists with that private profile. Values you apply later in the Emulator are temporary overrides and do not change the imported file. Keep the original file for re-import after reinstalling or changing devices. See the card-profile format and usage guide for the document structure and safety boundaries.
